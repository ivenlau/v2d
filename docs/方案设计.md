# V2D（Video to Disk）浏览器视频嗅探与转存插件 — 方案设计

> 版本：v1.0（评审定稿）｜日期：2026-09-23｜状态：已评审（结论见 §15）
>
> 一句话定位：**在浏览器里看到能播的视频，一键「存本地」或「秒转存到 115 网盘」，大文件零落盘负担。**

## 1. 目标与非目标

### 1.1 目标

| # | 目标 | 优先级 |
|---|---|---|
| G1 | 自动嗅探当前页面播放中的视频（含 HLS/DASH 分段流、blob 伪 URL 场景） | P0 |
| G2 | 下载到本地（桌面 Chrome，走原生下载管理器）——**默认下载行为，零配置即用** | P0 |
| G3 | 转存到 115 网盘（智能多通道：离线下载 / 流式直传 / 秒传）——**默认关闭**，需设置开关 + 认证通过后才启用（见 §9.5） | P0 |
| G4 | 性能优先：常驻开销趋近于零、大文件（数 GB）内存有界、不卡页面 | P0 |
| G5 | 兼容性：通用嗅探覆盖任意网站 + 头部站点适配层（B站/腾讯/优酷等） | P0/P1 |
| G6 | iOS Safari 版（第二期，核心逻辑跨端复用） | P1 |
| G7 | 网盘抽象层，后续可扩展其他网盘 | P1 |

### 1.2 非目标（明确排除）

- **DRM 内容不支持**：Netflix / Disney+ / 各平台 VIP 加密流（Widevine/FairPlay/部分国内 self-DRM）技术上受 EME 保护，不做、不绕过。检测到 EME 加密时给出明确提示。
- **直播流录制不做**（HLS LIVE 只提示不支持，MVP 阶段）。
- **不做视频转码**（只 remux 转封装，不重编码）。
- **iOS Chrome 不在范围内**：iOS 版 Chrome 不支持任何扩展（截至 2026-09 调研确认），无技术路线，iOS 端唯一正规路线是 Safari Web Extension（见 §11）。
- **不内置任何人的 115 凭证/appid**：用户自行扫码授权（见 §7.6 安全说明）。

### 1.3 合规声明

产品内置免责声明：下载/转存受版权保护的内容可能违反目标网站服务条款，用户需自行承担合规责任；插件本身不破解任何保护措施，仅处理用户有权访问的明文媒体流。

## 3. 总体架构

### 3.1 形态与组成

Chrome 桌面扩展（Manifest V3），五个运行单元：

```
┌─────────────────────────────── Chrome 桌面 ───────────────────────────────┐
│                                                                           │
│  ┌─ Service Worker（后台协调者，轻量，可随时被杀）─────────────────────┐   │
│  │  · 嗅探引擎 A：webRequest 观察式监听（URL 模式过滤，常驻唯一开销）  │   │
│  │  · 媒体候选登记（chrome.storage.session）+ 角标计数                 │   │
│  │  · 115 API 客户端：鉴权/目录/离线任务/upload-init（轻请求）         │   │
│  │  · 传输队列状态机 + 消息路由（popup/管理页/content script）         │   │
│  │  · 限速器（0.3s+jitter）、日请求计数、指数退避                      │   │
│  └────────────────────────────┬──────────────────────────────────────┘   │
│                     消息/心跳 │                                          │
│  ┌─ Offscreen Document + 传输 Worker（重活，长生命周期）────────────────┐  │
│  │  · 传输管线：抓流→OPFS 暂存→增量 SHA1→秒传探测→OSS 分片直传→清理   │  │
│  │  · HLS 解析/分段并发下载/mux.js remux（流式边转边写）               │  │
│  │  · OPFS 通过 Worker 内 createSyncAccessHandle 读写（磁盘级、有界内存）│ │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                           │
│  ┌─ Content Script（按需注入，默认不注入任何页面）──────────────────────┐  │
│  │  · B 引擎：DOM 媒体扫描（popup 打开时注入当前标签页）               │  │
│  │  · C 引擎：MAIN world MSE/EME Hook（白名单站点或用户开关）          │  │
│  │  · 站点适配器（头部站点域名定向注入）                                │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                           │
│  Popup（候选列表+操作）  ｜  传输管理页（队列/进度/重试）  ｜  设置页     │
└───────────────────────────────────────────────────────────────────────────┘
```

**生命周期关键设计**：
- SW 只做「轻请求 + 调度」，任何 > 数 MB 的字节流都不经过 SW。
- 传输期间 Offscreen ↔ SW 互有心跳（双端保活，Chrome MV3 标准模式）；Offscreen 被杀时队列状态持久化在 `IndexedDB`，重启后续传。
- OPFS 暂存文件 + 队列元数据落盘 → 浏览器崩溃/重启也不丢进度（受限于 §7.4 STS 窗口约束）。

### 3.2 数据流总览（一次典型转存）

> 前置条件：115 功能已开启且认证有效（§9.5）。未启用时，用户可见的全部能力 = 嗅探 + 存本地。

```
用户点击「转存到115」
   │
   ▼
[通道决策器] ── 直链公开可拉 & 是115会员？ ──► 通道① 离线下载：add_task_urls → 轮询至完成（浏览器零流量）
   │
   ├─ m3u8/DASH/需登录态 ──► 通道② 流式直传（主通道，详见 §6）
   │
   └─ 用户勾选「同时存本地」 ──► chrome.downloads 原生下载（或暂存文件另存）
```

## 4. 视频嗅探引擎（三引擎分级，性能优先）

### 4.1 引擎 A：webRequest URL 嗅探（常驻，唯一默认开启项）

- `chrome.webRequest.onBeforeRequest / onCompleted`（MV3 观察式，不阻断），SW 内运行。
- URL 模式预过滤（廉价字符串匹配）：`.m3u8` `.mpd` `.mp4` `.m4s` `.ts` `.webm` `.flv` `.mov` `.mkv` `.aac` `.mp3` 及常见 CDN 路径特征；命中才进登记逻辑。
- 请求头捕获：记录 `content-type`、`content-length`、Referer 等，用于后续拉流与类型判断。
- **页面零注入、零性能损耗**；这是全插件对普通网页唯一的常驻成本。

### 4.2 引擎 B：DOM 扫描（按需）

- 打开 popup 时对当前标签页 `chrome.scripting.executeScript`（activeTab 权限）扫描 `<video>/<audio>/<source>` 的 `src`、`currentSrc`，合并进候选列表。
- 不做 MutationObserver 常驻监听（避免 SPA 页面持续开销）；SPA 场景靠引擎 A 的持续网络监听兜底。

### 4.3 引擎 C：MSE Hook（深捕获，默认关，按站点/用户开关）

- 场景：站点把流喂给 `MediaSource`，页面只见 `blob:` URL，引擎 A 拿到的是分段请求（多数站点其实够用）。
- 实现：`chrome.scripting.registerContentScripts`（`world: "MAIN"`，Chrome 111+）注入 hook 脚本，包装 `MediaSource.prototype.addSourceBuffer` 的 `appendBuffer`，**透传同时**旁路 chunk（默认关闭时只做一层布尔判断，开销可忽略）。
- 自动触发条件：页面 `<video>.src` 为 `blob:` 且引擎 A 未发现任何 playlist → 对该标签页临时启用 C 引擎并提示用户。
- 捕获产物：按 SourceBuffer mimeType 分轨聚合 → 走与 HLS 相同的 remux→转存管线。
- **DRM 识别**：Hook `navigator.mediaKeys`/`requestMediaKeySystemAccess`/`encrypted` 事件 → 标记 DRM，拒绝并提供说明。

### 4.4 候选列表治理（易用性核心）

- 去重（URL 指纹 + size + type）、按「可能是正片 > 音轨 > 字幕/封面」排序打分：`content-length` 大小、mimeType、是否 master playlist（含多码率则展开为清晰度子项）、文件名线索（URL path / `Content-Disposition` / 页面 `<title>`）。
- 懒探测：列表展示时不发探测请求；用户点击某项时才发 `Range: bytes=0-0` 探测真实大小/可拉性。
- 存储于 `chrome.storage.session`（SW 重启不丢、浏览器关闭自动清），上限裁剪（每标签页 100 条）。

## 5. HLS / DASH 处理与 Remux（决策：remux 为 MP4）

### 5.1 HLS（m3u8）

```
master.m3u8 ─展开─► 多码率候选
   │
media.m3u8 ─解析─► 分段列表（含 EXT-X-KEY）
   │                  │ AES-128 → WebCrypto AES-CBC 逐段解密（SAMPLE-AES/DRM 不支持）
   ▼                  ▼
分段并发下载（窗口式并发 4~6，按序写入）
   ▼
mux.js Transmuxer（TS → fMP4，纯转封装不转码，~百 KB）
   ▼
流式写入 OPFS 暂存文件（同时增量计算 SHA1）── 单遍完成，内存有界
```

- 直播流（`EXT-X-ENDLIST` 缺失）→ 提示不支持。
- 分段 URL 相对路径解析、`EXT-X-MAP`（init 段）、`BYTERANGE` 支持。

### 5.2 DASH / 分离音视频轨（如 B站）

- 音轨/视频轨分离的 fMP4（m4s）：`mp4box.js` 解封装 + `mp4-muxer` 合成单个 MP4（均为轻量库，合计 <1MB，不转码）。
- 流程：两轨并行分段下载 → 样本级对齐写入 → 输出 mp4 → 同一暂存管线。
- 归入站点适配层迭代（M5），MVP 的通用嗅探对 DASH 站点先提供「视频轨/音频轨分开转存」的降级选项。

### 5.3 产物

统一输出 **单个 `.mp4`**（fMP4，moov 前置），115 网页预览与主流播放器直接可播；文件名规则：`<页面标题/适配器提供的标题>_[<清晰度>].mp4`，非法字符清洗。

## 6. 通道② 流式直传管线（核心，性能优先）

> 本管线仅在 115 功能开启且认证有效时可达（§9.5）；未开启时插件全部行为 = 嗅探 + 本地下载。

### 6.1 为什么必须「暂存后再传」，而不是纯内存管道

115 上传协议要求先提交**整文件 SHA1** 才能发起 `upload/init`（秒传探测），且命中与否、是否二次区间校验都在上传开始前确定 → 字节至少要「可二次读」。纯内存不可行（数 GB），本地随机文件扩展不可读（沙箱）。**OPFS（Origin Private File System）是唯一既受浏览器管理、又可被扩展读写、且落盘的存储**：

- `<50MB` 小文件：全程内存，跳过 OPFS（快速路径）。
- `≥50MB`：OPFS 暂存。`unlimitedStorage` 权限解除配额限制；Worker 内 `createSyncAccessHandle` 提供高性能磁盘读写。

### 6.2 管线状态机

```
FETCH ──► STAGE ──► HASH/INIT ──► 秒传命中? ──是──► DONE(零上传，提示"115已有此内容")
  │          │           │              │
  │          │           │              否
  │          │           ▼              ▼
  │          │      （sign_check 二次区间校验则回读区间再 init）
  │          │              │
  │          │              ▼
  │          └─────► UPLOAD（STS get_token → OSS multipart 严格串行 → complete+callback）
  │                         │
  └─ 任意失败/中断 ─► PAUSED/FAILED（IndexedDB 持久化断点；OPFS 保留；可恢复）
DONE 后：删除 OPFS 暂存（若用户勾选「同时保存本地」→ 另存/保留）
```

各阶段要点：

1. **FETCH/STAGE**：直链流式拉取（SW 发起 fetch，body 流导入传输 Worker）；HLS 则按 §5.1 边转边写。拉流分级容错（§6.4）。
2. **HASH**：`hash-wasm` 增量 SHA1（WebCrypto `digest` 不支持流式），随写入同遍计算，零额外读盘。
3. **INIT**：调 115 `upload/init`（§7.2）；响应含 `sign_key+sign_check` 时回读区间（OPFS seek 读，毫秒级）补 `sign_val` 再 init 一次。
4. **UPLOAD**：OSS 直传，严格串行（F5），分片大小按 tg115bot 同款策略（10MB 起倍增至 ≤10000 片）；每片 ETag 记入 IndexedDB。
5. **清理**：`complete` 返回 <400 即成功（115 通过 `x-oss-callback` 异步入库）；删除暂存，出队列。

### 6.3 内存模型（性能承诺）

| 路径 | 常驻内存 |
|---|---|
| 离线通道 | ≈0 |
| 本地下载 | ≈0（原生 downloads） |
| 直传 <50MB | ≤ 文件大小（一次性） |
| 直传 ≥50MB | 分片缓冲 × 并发数 ≈ 数十 MB 上限，与文件大小无关 |

### 6.4 拉流容错分级（防盗链/CORS）

MV3 后台 fetch（有 host 权限）可跨域拉流但**无法自定义 Referer**，少数站点校验 Referer 会 403。分级降级：

1. **L1 后台直拉**（覆盖绝大多数，含带 URL token 的 CDN 链接）；
2. **L2 页面上下文拉取**：借 content script 在源站页面里 fetch（自动带对 Referer/Cookie）；
3. **L3 引导**：提示用户先播放该视频（触发引擎 A 捕获完整分段列表）或使用「MSE 深捕获」开关。

### 7.1 鉴权（PKCE 设备扫码）

| 步骤 | 端点 | 说明 |
|---|---|---|
| ① 取扫码凭证 | `POST https://passportapi.115.com/open/authDeviceCode`（form：`client_id`、`code_challenge`、`code_challenge_method=sha256`） | 返回 `uid/time/sign/qrcode`，插件用 `qrcode` 库在设置页渲染二维码 |
| ② 轮询状态 | `GET https://qrcodeapi.115.com/get/status/` | `0` 待扫 / `1` 待确认 / `2` 成功 / `-1` 过期 / `-2` 取消；每 2~3s，120s 超时 |
| ③ 换 token | `POST https://passportapi.115.com/open/deviceCodeToToken`（`uid`、`code_verifier`） | 得 `access_token + refresh_token` |
| ④ 刷新 | `POST https://passportapi.115.com/open/refreshToken`（`refresh_token`） | **单会话轮换**：刷新即吊销旧 token |

- PKCE：verifier 64 字符（url-safe 字母表），challenge = base64url(sha256(verifier))。
- 业务请求统一 `Authorization: Bearer <access_token>`；成功判定 `code==0` 或 `state==true`。
- 错误码处理（照抄 tg115bot 语义）：`40140125` token 过期→刷新重试一次；`40140126` 被其他会话刷新→先自行刷新重试；`40140116/40140119` 授权解除→必须重新扫码。
- **单会话互踢风险**：同一 115 账号同时给 tg115bot 和本插件用会互相吊销 token（见 §12 R3）。缓解：优先建议专用账号/会员子账号；插件同样实现「被踢后自动重扫码引导」；进阶选项：设置页支持「从 tg115bot 导入 token」（粘贴，二选一使用）。

### 7.2 上传协议（对照 `oss.py` / `oss_upload.py`）

| 步骤 | 端点/目标 | 关键参数与判定 |
|---|---|---|
| 目录 | `GET proapi.115.com/open/folder/get_info?path=`；`POST /open/folder/add`（`pid`,`file_name`） | `code==20004` 视为已存在；建目录后短重试取 cid；根目录 cid=0 |
| 秒传探测 | `POST proapi.115.com/open/upload/init`（form：`file_name`、`file_size`、`target=U_1_<cid>`、`fileid=<整文件SHA1大写>`） | ⚠️ **开放平台无 128KB preid**，用整文件 SHA1；`data.status=="2"` = 秒传命中 |
| 二次校验 | 响应含 `sign_key` + `sign_check`（`"start-end"` 闭区间）→ 对区间算 SHA1 大写为 `sign_val`，带 `sign_key/sign_val` 重调 init | 区间回读自 OPFS，开销极小 |
| STS 凭证 | `GET proapi.115.com/open/upload/get_token` | 返回 `AccessKeyId/AccessKeySecret/SecurityToken/endpoint`；**每次全新，与会话绑定** |
| OSS 地址 | `http(s)://{bucket}.{endpoint}/{quote(object, safe='/')}` | 标准 OSS V1 签名（HMAC-SHA1，WebCrypto 可实现），`x-oss-security-token` 参与字典序签名 |
| ≤10MB | 单次 `PUT` + callback 头 | 带 `x-oss-callback` / `x-oss-callback-var`（init 响应 base64）否则 115 不入库 |
| >10MB | `POST {obj}?sequential=1&uploads=1` → 逐片 `PUT ?partNumber=N&uploadId=` → `POST ?uploadId=` complete（XML body + callback 头） | **严格串行**，分片从 1 起；ETag 原样保留；complete 成功即 HTTP <400 |

### 7.3 离线下载通道

- `POST proapi.115.com/open/offline/add_task_urls`（`urls=<单个URL>`、`wp_path_id=<cid>`）
- `GET /open/offline/get_task_list?page=N` 轮询：`status` `-1` 失败 / `1` 进行 / `2` 完成，`percentDone` 展示；完成即 `del_task(del_source_file=0)` 清记录
- `GET /open/offline/get_quota_info` 查离线配额
- 适用判定：非 m3u8/非 blob、URL 公网可达（无 Referer/Cookie/内网限制）、会员身份。轮询自适应（3s→10s 退避，节省 §7.5 的日请求额度）。

### 7.4 已知协议硬约束（必须在产品层显式处理）

1. **STS ↔ multipart 绑定**：上传中途刷新 STS = 已传分片全部作废（`NoSuchUpload`，tg115bot 中 `OssSessionLostError`）。⇒ **大文件必须在一个 STS 有效期内传完**。产品对策：发起上传前用「文件大小 ÷ 实测上行速度」预估时长，超窗风险时明确警告（如 `预计 95 分钟 > STS 窗口约 60 分钟`）；失败后整体重传一次，再失败标记永久失败。
2. **严格串行分片** ⇒ 单连接吞吐，上传速度 ≈ 上行带宽，无并发加速手段（协议约束，接受）。
3. **限速与配额**（复刻 tg115bot 策略）：proapi 请求最小间隔 0.3s + 0~0.2s 抖动；**日计数上限 9500**（官方 10000 打 0.95 折）；指数退避（base 2s）。OSS 分片请求不计入。
4. **UA**：tg115bot 全链路用 Chrome UA；浏览器扩展天然带 Chrome UA，无需处理（fetch 也不允许覆写 UA，正好一致）。

### 7.5 网盘抽象层（G7）

```
CloudProvider 接口：auth() / pickTargetFolder() / ensureFolder(path)
                  / offlineAdd(url) / uploadInit(meta) / getSts() / ...
implementations:  `115OpenProvider`（本期） | 未来: `AliyunDriveProvider` `BaiduProvider`…
```
上传管线只依赖接口；115 特有语义（秒传/二次校验/串行分片）下沉到 provider 内部。

### 7.6 安全说明

- token 存 `chrome.storage.local`（浏览器 profile 边界内）；不上传任何遥测；不内置任何 appid/token，用户用插件内置的 client_id 自行扫码（与 tg115bot 同款公共测试 client_id，可在设置中覆盖为自己的 app_id）。
- 权限最小化见 §10。

## 10. 权限与安全

| 权限 | 用途 | 说明 |
|---|---|---|
| `webRequest`（观察式） | 引擎 A 嗅探 | MV3 合法用法，同类产品通行 |
| `host_permissions: <all_urls>` | 跨站嗅探 + 后台拉流（视频源站点任意） | 视频下载类的必要权限；上架时附用途说明 |
| `optional_host_permissions`（`*.115.com`、`*.aliyuncs.com` 等） | 115 API 与 OSS 直传请求 | **随 §9.5 开关在启用时动态申请**：未启用 115 的用户不携带任何 115 相关授权，安装时权限面最小化（利于商店审核，与「默认关闭」的产品语义一致） |
| `downloads` | 本地下载 | |
| `storage` + `unlimitedStorage` | 配置/队列 + OPFS 大文件暂存 | |
| `scripting` + `activeTab` | 按需 DOM 扫描（引擎 B） | |
| `offscreen` | 传输 Worker 宿主 | |
| `sidePanel`（可选） | 侧栏传输进度 | 不装也不影响核心功能 |
| 可选 `nativeMessaging`（仅二期 iOS） | 与自家壳 App 通信 | |

- 无远程代码、无 eval；content script 不读取页面无关数据；`<all_urls>` 仅用于媒体 URL 匹配与媒体字节拉取。
